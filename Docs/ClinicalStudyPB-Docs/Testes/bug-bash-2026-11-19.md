### 4.1. Severidade

| Nível | Quando usar | Exemplo |
| --- | --- | --- |
| Crítica | Bloqueia fluxo principal ou expõe acesso indevido | Pesquisador inclui candidato sem permissão |
| Alta | Funcionalidade principal não funciona | Cadastro de estudo não salva |
| Média | Funcionamento parcial ou mensagem errada | Mensagem genérica em vez da específica |
| Baixa | Texto, layout ou detalhe visual | Botão desalinhado ou texto inconsistente |

#### Bug #1: [Usuários / API] Administrador consegue desativar o próprio usuário pela API

```text
Caso do roteiro: R-05
Data do teste: 23/11/2026
Testado por: Mirelle Casimiro
Perfil usado: ADMINISTRADOR
Ambiente: Docker Compose, develop no commit 1fb0e82 + PRs #62, #63, #67 e #68; API em http://localhost:8080/api

Passos para reproduzir:
1. Entrar como admin@clinicalstudypb.test (POST /api/auth/login) e guardar o token.
2. Consultar o próprio id (GET /api/auth/me): id 1.
3. Enviar PATCH /api/usuarios/1/status com {"ativo": false} e o token do próprio administrador.
4. Tentar entrar de novo com admin@clinicalstudypb.test.

Resultado esperado: a API recusa a desativação do próprio usuário com uma mensagem de bloqueio,
como a tela já faz ("Você não pode desativar o próprio usuário."), e a conta continua ativa.
Resultado obtido: a API responde 200 e desativa a conta. O login do administrador passa a responder
401 USUARIO_INATIVO. Se ele for o único administrador, ninguém mais consegue gerenciar usuários.

Severidade: Média (a tela bloqueia; a regra falta só na API, que pode ser chamada direto pelo Swagger ou por outra ferramenta)
Evidência: evidencias/bug-bash-release2/R-05.png (tela bloqueando) e evidencias/bug-bash-release2/api-casos-2026-11-23.json (caso R-05, resposta 200)
Responsável pela correção: Mirelle Casimiro
Sugestão de correção: no UsuarioService, recusar a desativação quando o id do usuário for o do token
(por exemplo, 409 com um código próprio), e cobrir com teste unitário e de integração.

Reteste:
- Data do reteste: 23/11/2026
- Retestado por: Mirelle Casimiro
- Teve problema? Não
- Resultado: Corrigido. `UsuarioStatusIntegrationTest` confirmou que a API retorna 409
  (`USUARIO_PROPRIO_DESATIVACAO`), mantém a conta ativa e permite desativar outro usuário.
- Validação complementar: `UsuarioServiceTest`, `UsuarioControllerTest` e `AutorizacaoTest`.
- Card/tarefa individual no Azure: não criado, conforme decisão; o defeito permanece registrado
  neste documento.
```
